# 微信输入法 (WeType) PC 版常用语全量导出工具

> **一键免破解、无损导出微信输入法中的全部常用语（快捷短语）及对应输入码。**  
> 支持导出为 JSON、CSV 表格以及搜狗 / Rime / 微信等主流输入法直接支持的通用词库格式。

---

## ⚡ 快速开始 (Quick Start)

本项目采用纯标准库构建，**零外部 pip 依赖**，开箱即用。

### 方法 A：Windows 双击一键运行 (最推荐)
直接双击项目根目录下的批处理脚本：
- 👉 **`export.bat`**

> 批处理脚本已做 100% 纯 ASCII 化处理，兼容所有 Windows 语言环境，耗时仅需 1~2 秒，并在完成后保持窗口展示统计结果。

### 方法 B：使用 UV 命令行运行
```powershell
# 1. 常规直接导出
uv run python main.py

# 2. 自动重启刷新输入法后导出（推荐在刚删减/修改了常用语时使用）
uv run python main.py -r
```

### 方法 C：直接使用 Python 虚拟环境
```powershell
".venv\Scripts\python.exe" main.py
```

### 📁 导出文件在哪里？
运行完成后，所有结果自动生成在 **`result/`** 目录中（该目录已被 `.gitignore` 自动保护，绝不上传个人隐私）：
- `result/微信输入法常用语_导出.json`：包含条目 ID、输入码、文本正文的结构化数据。
- `result/微信输入法常用语_导出.csv`：Excel / WPS 可直接双击打开查看的表格文件。
- `result/微信输入法常用语_导出_通用词库.txt`：标准输入法短语格式，可直接导入各大主流输入法。

## 1. 词库迁移指南 (导入其他输入法)

### 1.1 通用词库格式规范
导出的 `result/微信输入法常用语_导出_通用词库.txt` 采用各大输入法普遍支持的标准语法：
```text
输入码,候选位置=短语正文
```
- 多行长文本已自动统一转义（`\n`），保证单行语法完整；
- 未指定输入码的条目以 `# [无输入码] 内容` 注释行保留，不丢失任何信息。

### 1.2 迁移到搜狗输入法
1. 打开搜狗输入法「属性设置」；
2. 进入「高级」->「候选扩展」->「自定义短语」；
3. 点击「自定义短语设置」->「直接编辑配置文件」或「导入」；
4. 将 `微信输入法常用语_导出_通用词库.txt` 中的内容复制追加进去保存即可。

### 1.3 迁移到 Rime (中州韵 / 小狼毫)
1. 打开 Rime 用户文件夹（如 `%APPDATA%\Rime`）；
2. 打开对应的自定义词典文件（如 `custom_phrase.txt`）；
3. 将导出的文本按 `短语正文<Tab>输入码<Tab>候选位` 替换部署即可。

## 2. 核心排查结论与底层存储真相

在传统输入法中，常用短语通常以明文配置、SQLite 或明文数据库保存在本地磁盘。但对微信输入法（WeType）2.1+ 版本全盘深度排查表明：

### 2.1 磁盘为什么没有明文常用语文件？
- **全盘扫描 0 命中**：无论在 `AppData\Local`、`LocalLow`、`Roaming`、`ProgramData` 还是注册表中，对常用语正文进行明文与压缩解包扫描，结果均为 0。
- **纯云端同步核心**：微信输入法的常用语（在腾讯内部代号为 `common_terms` / `quick_use_info`）是由腾讯服务器统一管理的云端资产，随登录账号（UID）在手机端与电脑端之间双向多端同步。

### 2.2 磁盘 LevelDB 的真实角色
在 `%LOCALAPPDATA%Low\Tencent\WeType\DictDir2\user_hot_word\` 中，确实存在持久化数据库，但深入解析 SST (`.ldb`) 发现：
- 该库只保存了 **常用语的输入码哈希索引与热词 ID (`hw_id`)**（如 `hash/hw_id` 形式的二进制索引）。
- **目的**：打字时仅凭索引在本地实现微秒级倒排检索，判断是否需要弹出常用语。
- **结论**：磁盘上并未固化条目的完整明文内容，因此单纯试图在磁盘上“复制某个文件”来迁移常用语是行不通的。

### 2.3 运行时内存解构与突破
依据**第一性原理**：输入法在离线或正常使用时，面板要展示常用语、候选栏要上屏长文本，**完整的明文条目必然已解密并常驻在进程内存中**！
- 输入法架构包含两个核心宿主：
  1. `wetype_update.exe`：宿主 Flutter 设置窗口（`SettingFlutterWindow`），用于展示常用语设置面板。
  2. `wetype_server.exe`：输入引擎核心服务，内部维护连续的结构体数组供打字匹配。
- 只要输入法正常运行，通过 Windows API 挂钩内存即可直接读取 100% 完整、实时的常用语列表！

### 2.4 为什么刚删除的词条仍可能被扫描到？（内存残留机制）
- **根因**：当用户在界面中删除常用语时，UI 向后台和云端发送了删除指令，但 Flutter 进程堆（Heap）中历史通信使用的物理内存页**不会被操作系统立即清零**，而是作为游离碎片保留在已分配的物理页中。
- **解决机制**：全内存扫描工具会抓取到这些尚未被覆写的死内存；若近期刚删除了词条，只需通过 `-r` 参数（或执行 `taskkill`）重启输入法进程。后台系统服务会在 2 秒内重新拉起纯净进程，并重新从云端加载最新活跃条目，历史残留即被彻底清空。

## 3. 关键技术原理 (Flutter StandardMessageCodec 逆向)

微信输入法的客户端界面由 Flutter 驱动。C++ 宿主进程与 Flutter Dart 代码之间通过 **Platform Channel** 进行通信，其默认的数据封包协议即为 Flutter 的 **`StandardMessageCodec`**。

在 `wetype_update.exe` 堆内存中，常用语以规整的二进制流驻留（脱敏示范）：

```text
[0D 03]                     -> Map 标识 (包含 3 对 key-value)
  [07 05] "hw_id"           -> Tag 0x07 (String), Len 5, Key 名为 "hw_id"
  [07 0D] "1790000000000"   -> Tag 0x07 (String), Len 13, 唯一条目 ID
  [07 03] "key"             -> Tag 0x07 (String), Len 3, Key 名为 "key"
  [07 03] "sample_key"      -> Tag 0x07 (String), Len 3, 触发缩写 / 输入码
  [07 04] "text"            -> Tag 0x07 (String), Len 4, Key 名为 "text"
  [07 0B] "Sample Text"     -> Tag 0x07 (String), Len 11, 常用语正文内容
```

### 变长长度解码规则
如果字符串长度超过 253 字节（如长段落、多行代码片段、模板等），Flutter 编码协议会自动升级：
- `len < 254`：单字节表示长度；
- `len == 254`：后跟 2 字节小端整数 (`<H`)；
- `len == 255`：后跟 4 字节小端整数 (`<I`)。

本项目使用纯 Python 标准库完整实现了 `StandardMessageCodec` 反解引擎，在扫描进程可读内存段时，以纳秒级正则快速定位 `\x07\x05hw_id` 特征，无损提取出所有条目并做去重排序。

## 4. 调试与输入法自动重启

在开发调试或配置更新时，若需要重启微信输入法以重新拉取云端数据或重置内存状态，可在终端执行以下命令：

```powershell
# 强制终止用户端组件（系统后台服务 WeType Management Service 会在数秒内自动重新拉起引擎）
taskkill /F /T /IM wetype_server.exe /IM wetype_renderer.exe /IM wetype_update.exe
```
